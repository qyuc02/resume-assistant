# 简历助手

一个跑在本机的简历工作台：**事实只记一次，讲法可以有很多份**。

纯本地运行，数据只存在你自己电脑上，不上传任何服务器。

- **给普通用户（打包版）**：下载安装包双击安装即用，无需装 Node——见下方「三、运行 · 打包成桌面应用」。
- **给开发者（网页版）**：Windows 双击 `启动.bat`；Mac / Linux 看「三、运行」三条命令。

---

## 一、设计思路

### 1. 核心决定：把「事实」和「讲法」彻底分开

旧版所有麻烦的源头，都是把这两件事混在了一起。

- **经历档案 = 事实**。真实发生过的事，只记一次，永不改写。
- **简历 = 讲法**。挑哪些经历、按什么顺序、每句话怎么说。

投 A 公司强调高并发，投 B 公司强调业务建模——不是两份不同的经历，
是**同一段事实的两种讲法**。所以在数据上：

```
Experience（档案，事实）  ──引用──>  ResumeItem（简历，讲法）
  bullets: string[]                  experienceId: 指向档案
                                     bulletsOverride: string[] | null  ← 为 null 就用档案原文
```

`bulletsOverride` 为 `null` 时直接读档案原文；一旦在简历里改了，就只写在这一份简历里，
档案原文一个字都不动。界面上会出现「本简历改写」标记，随时可以「还原为档案原文」。

**带来的好处**：同一段实习经历可以同时出现在 5 份简历里，各有各的讲法，
改其中一份不会污染其他 4 份，也不会污染档案。

### 2. 删掉了「求职方向 / 侧重变体」

旧版有四层优先级叠加：默认 → 方向变体 → 手动覆盖 → 修改记录。
任何一层缺个字段就白屏，实际使用时根本想不起来改的是哪一层。

新版直接砍掉：**一份简历就是一套讲法**。想换个讲法 → 复制一份简历 → 改。
层级从 4 层降到 1 层，心智负担和崩溃概率一起归零。

### 3. 服务端归一化：前端永远看不到 `undefined`

所有数据在服务端进出都过一遍 `normalizeData`，缺字段补默认值、类型不对就纠正。
前端拿到的对象结构永远完整，`.trim()` / `.replace()` / `.map()` 不会再炸。
数据带 `schemaVersion`，以后加字段可以平滑迁移。

这也是旧版白屏的直接原因——旧数据里没有新字段，组件直接读 `undefined.replace()`。

### 4. 存储放在服务端文件，不用 localStorage

数据落在项目目录 `data/app-data.json`。换成服务端文件的好处：

- 网页版和桌面版不会再有两份数据（旧版就是这么分裂的）
- 每次保存自动留一份带时间戳的备份（保留最近 20 份）
- 写盘用原子操作（先写 `.tmp` 再 `rename`），写一半断电也不会得到半个坏文件
- 文件真读坏了会自动隔离到 `data/backups/corrupt-*.json`，然后给一份干净的，不让应用打不开

### 5. AI 是可选增强，不是依赖

不填 API Key，其余功能 100% 可用。AI 只用来做两件事：解析导入的简历、对照 JD 给改写建议。
建议永远以「草稿」形式给出，你确认采纳才写入，且只写进当前这份简历。

## 二、功能清单

### 经历档案（事实层）
- 分类管理：默认 教育经历 / 实习与工作 / 项目经历 / 技能与证书，可增删改名
- 经历增删改：标题、职位、起止时间、地点、要点（一行一条）、关键词标签
- 分类内上下移动排序
- 从 Word / txt / md 导入简历，自动拆成分类和经历（需 AI Key；也可纯文本导入）
- 删除经历时，引用它的简历会自动移除对应条目，不留悬空引用

### 简历（讲法层）
- 多份简历并存，可新建 / 复制 / 重命名 / 删除
- 从档案挑经历加入，或一键「全部加入」
- 简历内调整顺序、移除条目
- 逐条改写要点，带「本简历改写」标记与「还原为档案原文」
- 专属个人简介（`summaryOverride`），同样可一键还原
- 版本快照：改之前存一份，可从快照恢复（恢复前自动把当前状态也存一份）
- 对照岗位 JD 诊断，逐条给出建议，采纳 / 忽略
- 实时预览：所见即所得的 A4 排版
- 导出 Word（.docx）、浏览器打印 / 存 PDF（已适配打印样式）

### 投递记录
- 新增岗位：公司、职位、城市、薪资、渠道、链接、JD、下一步行动
- 阶段推进：待投递 → 已投递 → 笔试 → 面试 → offer / 已结束
- 优先级、搜索、筛选、排序
- 投递时冻结简历快照，事后修改简历不影响当时投出去的版本
- 详情抽屉查看完整历史

### 设置
- 个人基本信息（姓名、电话、邮箱、城市、主页、GitHub、个人简介）
- DeepSeek API Key（可选，存在浏览器 localStorage，不进数据文件）
- JSON 备份导出 / 导入
- 清空数据

## 三、运行

### 打包成桌面应用（给非技术用户）

想把软件发给不懂技术的朋友用，打包成安装包，对方双击即用，**不需要装 Node、不需要命令行**。
打包版的数据存在系统用户目录（Windows `%APPDATA%\简历助手\data`，macOS `~/Library/Application Support/简历助手/data`），和网页版互不影响。

**Windows 安装包**（在当前这台电脑上即可打包）：

```bash
npm run pack:win      # 或 npm run pack
```

产物在 `release/简历助手 Setup x.x.x.exe`。

**macOS 安装包**（`.dmg` 只能在 macOS 上构建，Windows 本机打不出来）：

- 在 Mac 上：克隆仓库 → `npm install` → `npm run pack:mac`，产物在 `release/简历助手-x.x.x-{arm64,x64}.dmg`（arm64 给 Apple 芯片，x64 给 Intel 老款）。
- 没有 Mac：把仓库推到 GitHub，用本仓库自带的 Actions（`.github/workflows/build.yml`）在云端自动打包，完事在 Actions 页面下载 `简历助手-mac` 产物即可。

> 未签名的 mac 包首次打开时系统会拦一道「无法验证开发者」。对方在 Finder 里**右键点应用 → 打开**（或终端跑 `xattr -cr /Applications/简历助手.app`）一次即可，属 macOS 对未付费开发者账号的正常限制，不影响使用。

### 前置要求

- **Node.js 18 或更高**（`node -v` 查看），推荐 20 / 22
- 不需要数据库、不需要注册账号

### 获取并启动

```bash
git clone https://github.com/qyuc02/resume-assistant.git
cd resume-assistant

npm install      # 安装依赖，约 100 个包
npm run build    # 构建前端，必须执行（dist/ 不进版本库）
npm start        # 启动，然后打开 http://localhost:4173
```

三步通常十几秒完成。

**`npm run build` 不能跳过**：构建产物 `dist/` 故意不提交到仓库，
所以刚克隆下来是没有 `dist/` 的。直接 `npm start` 会提示「未找到 dist 构建产物」，
首页打不开。这是设计如此，不是装错了。

### 一键启动

- **Windows**：双击 `启动.bat`。
- **macOS / Linux**：终端执行 `bash 启动.sh`。

脚本会自动做完上面三件事并弹出浏览器窗口。它**先构建再启动**是刻意的：
旧版曾优先运行已打包的 EXE，导致「改了代码却没生效」。现在保证运行的永远是当前源码。

### 其它

- 开发模式：`npm run dev`（Vite 热更新，端口 5173）
- 换端口：`PORT=8080 npm start`；Windows 下用 `set PORT=8080 && npm start`
- 禁止自动开浏览器：`NO_OPEN=1`
- 首次启动是空白数据，`data/` 目录会自动创建，不需要手动建
- 关闭服务：在终端按 `Ctrl+C`

## 四、目录结构

```
├── 启动.bat              # 唯一入口：构建 + 启动
├── electron/
│   └── main.mjs          # Electron 主进程（桌面版入口）
├── server/
│   ├── index.mjs         # 静态托管 + /api/data + /api/ai
│   ├── schema.mjs        # 数据结构定义与归一化（唯一事实来源）
│   ├── store.mjs         # 原子写盘、备份、损坏隔离
│   └── ai.mjs            # DeepSeek 代理
├── src/
│   ├── types.ts          # 前端类型（与 schema.mjs 对齐）
│   ├── App.tsx           # 全局状态、自动保存、页签
│   ├── api.ts            # 数据读写 / AI 调用
│   ├── util.ts           # 通用工具
│   ├── docx.ts           # Word 导出
│   ├── extract.ts        # 简历文本提取
│   ├── views/            # 四个页面
│   └── components/       # 弹窗、图标、简历纸张
├── data/
│   ├── app-data.json     # 你的数据
│   ├── logos/            # 公司 logo 本地缓存
│   └── backups/          # 自动备份
├── release/              # 打包产物（gitignore）
└── _legacy/              # 旧版代码归档，不参与构建
```

## 五、已解决的历史问题

| 问题 | 根因 | 修复 |
|---|---|---|
| 打开就白屏 | 旧数据缺新字段，组件读 `undefined.replace()` | 服务端统一归一化 |
| 改了代码却没生效 | 启动脚本优先跑旧 EXE 并提前 `exit` | 改用 `启动.bat`，每次先构建 |
| 编辑莫名丢失 | 自动保存死循环 + 旧响应覆盖新数据 | 版本号机制，丢弃过期响应 |
| 网页版与桌面版数据分裂 | 两边用不同存储 | 统一到服务端文件 |
| 四层覆盖互相打架 | 方向/变体/覆盖/记录叠加 | 砍到一层：一份简历一套讲法 |

详见 `开发日志.md`。
